# Foreign Function Interface for LLMs

We had a tool for writing software. It was called software.

Now we can write the specifications using text, and a large language model generates the implementation.

```python
from llm_ffi import llm_impl

@llm_impl
def parse_legacy_format(data: str) -> dict[str, str]:
    """Parse pipe-delimited format: account|balance|date

    Return dict with keys: account, balance, date
    """
    raise NotImplementedError
```

Run it, and it works.

## Three Modes

**Normal mode** (default): Generate code files in advance
```bash
llm-ffi generate mymodule.py
python mymodule.py
```

**Runtime generation**: Generate on-demand when functions are called
```bash
LLM_FFI_DANGER_MODE=true python mymodule.py
```

With runtime generation code is generated on first call, cached in memory, and cleared on restart.

**More danger mode**: Generate and execute fresh code on every function call
```bash
LLM_FFI_MORE_DANGER_MODE=true python mymodule.py
```

This takes precedence over saved implementations and both in-memory implementation caches.
It works independently of `LLM_FFI_DANGER_MODE` and never saves or caches the generated code.
Every call is a new opportunity to make no mistakes.

## Installation

```bash
pip install llm-ffi
```


## Usage

If you were using this more carefully, you could do;

### 1. Write the spec

```python
from llm_ffi import llm_impl

@llm_impl
def parse_legacy_format(data: str) -> dict[str, str]:
    """Parse pipe-delimited format: account|balance|date

    Return dict with keys: account, balance, date
    """
    raise NotImplementedError
```

**The docstring is the spec.** Be precise about inputs, outputs, edge cases.

### 2. Generate implementation

```bash
llm-ffi generate mymodule.py
```

Creates `mymodule_llm_generated/parse_legacy_format.llm_generated.py`:
```python
"""
AUTO-GENERATED by llm-ffi - DO NOT EDIT
Generated: 2024-11-22T15:30:00Z
Spec Hash: 7a3f9c2e8b4d
"""

def parse_legacy_format(data: str) -> dict[str, str]:
    """Parse pipe-delimited format: account|balance|date

    Return dict with keys: account, balance, date
    """
    parts = data.split('|')
    return {"account": parts[0], "balance": parts[1], "date": parts[2]}
```

### 3. Write tests

```python
def test_parse_legacy_format():
    result = parse_legacy_format("CHK001|1500.00|2024-11-22")
    assert result == {
        "account": "CHK001",
        "balance": "1500.00",
        "date": "2024-11-22"
    }
```

Tests cross the FFI boundary. **If you can't specify it well enough to test, write it yourself.**

## Workflow

### Regeneration is spec-driven

```bash
# Only regenerates functions where spec (signature/docstring) changed
llm-ffi generate mymodule.py

# Force regenerate all (e.g., after model upgrade)
llm-ffi generate mymodule.py --force
```

Spec hash in stub updates automatically:
```python
raise NotImplementedError  # llm-ffi:7a3f9c2e8b4d:9f8e2d1ac7b5
```

### Review process

PR diff shows:
```diff
 @llm_impl
 def parse_legacy_format(data: str) -> dict[str, str]:
-    """Parse pipe-delimited format: account|balance|date"""
+    """Parse pipe-delimited format: account|balance|date|status"""
-    raise NotImplementedError  # llm-ffi:7a3f9c2e8b4d:9f8e2d1ac7b5
+    raise NotImplementedError  # llm-ffi:8b4e0d3fa1c9:a1c9f3e74d8b
```

Hash change visible. Reviewer:
1. Reviews spec change (docstring)
2. **Reviews tests** (not generated code)
3. Verifies tests pass

### Context access

Generated code can access module-level constants/helpers via late binding:

```python
# mymodule.py
TIMEOUT = 30

@llm_impl
def fetch_with_timeout(url: str) -> str:
    """Fetch URL with module TIMEOUT constant"""
    raise NotImplementedError
```

Generated code imports inside function:
```python
def fetch_with_timeout(url: str) -> str:
    import mymodule
    import requests
    return requests.get(url, timeout=mymodule.TIMEOUT).text
```

## Commands

```bash
# Generate implementations
llm-ffi generate mymodule.py

# Force regenerate all (e.g., after model upgrade)
llm-ffi generate mymodule.py --force

# Clear generated code
llm-ffi clear mymodule.py
```

## Configuration

`.env` file:
```bash
API_KEY=sk-ant-...                    # Required (Anthropic API key)
MAX_TOKENS=4096                       # Optional (default shown)
```

Environment variables:
```bash
LLM_FFI_DANGER_MODE=true             # Enable cached runtime generation
LLM_FFI_MORE_DANGER_MODE=true        # Generate and execute fresh code on every call
LLM_FFI_MODEL=claude-sonnet-4-5-20250929  # Override model (optional)
```

Both danger-mode flags accept `true`, `1`, or `yes` (case-insensitive).

Currently supports Claude models via Anthropic API. Support for other LLM providers might be added.
